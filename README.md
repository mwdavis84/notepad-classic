# Notepad Classic

A deliberately small, fast Windows text editor written in Rust against the raw
Win32 API. The editor is the standard Windows `EDIT` control; there is no GUI
framework, background service, telemetry, network access, updater, or plugin
system.

## Build

Install Rust 1.85 or newer with the MSVC toolchain and the Visual Studio Build
Tools with the **Desktop development with C++** workload (and optionally the **MSVC C++ ARM64 build tools** component for ARM64 cross-compilation), then run on Windows.
Rust 1.85 is the minimum because the project uses Edition 2024.

### x64 (Intel / AMD)
```powershell
cargo build --release --target x86_64-pc-windows-msvc
```

### ARM64 (Snapdragon / Surface Pro & Laptop)
```powershell
rustup target add aarch64-pc-windows-msvc
cargo build --release --target aarch64-pc-windows-msvc
```

The standalone executable is written to
`target\<target>\release\notepad-classic.exe` (or `target\release\notepad-classic.exe`).

The executable includes a native Windows icon resource with 16, 20, 24, 32,
40, 48, 64, 128, and 256 pixel variants, so the app icon is used in Explorer,
the taskbar, Alt+Tab, and the window caption without needing a sidecar file.

The release profile uses size optimization, whole-program LTO, one codegen unit,
symbol stripping, and aborting panics. These settings trade a slower build for a
smaller executable and avoid unwinding machinery without adding runtime work.

The initial editor font is Lucida Console Regular 10 point, matching the classic
Windows Notepad default. It can be changed for the current run with
**Format > Font**; version 1 deliberately remembers no settings between runs.

## Text formats

New documents are saved as UTF-8 without a BOM. Existing UTF-8, UTF-8 BOM, and
UTF-16 LE BOM files retain their encoding when saved. Other input is decoded
with the active Windows ANSI code page and saved as UTF-8.

## MSIX Packaging (Microsoft Store & Sideloading)

`package-msix.ps1` produces Windows Store-compatible packages validated with `makeappx.exe`.

### Build Individual Architecture Packages

```powershell
# x64 package: target\notepad-classic_<version>_x64.msix
powershell -ExecutionPolicy Bypass -File .\package-msix.ps1 -Target x86_64-pc-windows-msvc

# ARM64 package: target\notepad-classic_<version>_arm64.msix
powershell -ExecutionPolicy Bypass -File .\package-msix.ps1 -Target aarch64-pc-windows-msvc
```

### Build Multi-Architecture Bundle (x64 + ARM64)

To build both architectures and generate a unified `.msixbundle` in one step:

```powershell
# Produces both .msix files and target\notepad-classic_<version>.msixbundle
powershell -ExecutionPolicy Bypass -File .\package-msix.ps1 -Bundle
```

### Microsoft Partner Center / Store Submission

When submitting to [Microsoft Partner Center](https://partner.microsoft.com/):
- **Option 1 (Individual MSIX Packages - Recommended)**: Upload both `notepad-classic_<version>_x64.msix` and `notepad-classic_<version>_arm64.msix` to the **Packages** step of your Store submission. The Store reads `ProcessorArchitecture` from each package manifest and automatically delivers the native ARM64 build to Surface / Snapdragon devices and x64 to Intel / AMD devices.
- **Option 2 (Unified Bundle)**: Upload `notepad-classic_<version>.msixbundle` generated by `-Bundle`.

Microsoft automatically signs the package during Store ingestion.

### Local Testing & Sideloading

To build, bundle, and sign with a local self-signed test certificate for immediate installation:

```powershell
# Sign single architecture
powershell -ExecutionPolicy Bypass -File .\package-msix.ps1 -Target x86_64-pc-windows-msvc -SignForLocalTesting
powershell -ExecutionPolicy Bypass -File .\package-msix.ps1 -Target aarch64-pc-windows-msvc -SignForLocalTesting

# Build, bundle, and sign the unified bundle
powershell -ExecutionPolicy Bypass -File .\package-msix.ps1 -Bundle -SignForLocalTesting
```
